# Frontend screenshots

After changing a frontend's visible appearance or behavior, capture a real screenshot of the resulting interface and include it in the final response when the current environment supports capture and image delivery. This applies to layout, styling, components, typography, colors, animation states, and responsive changes.

Use the browser and image delivery capabilities actually available in the current environment, including T3 Code, Codex, Claude, or OpenCode where supported. Show the changed area at a useful viewport; include additional views when needed to demonstrate responsive or materially different states. Embed the image when supported, or provide an accessible link to the screenshot. Do not substitute a mockup or describe an image as captured when it was not.

Follow the environment's browser and tool restrictions. If capture or delivery is unavailable, or the application cannot reasonably be run, briefly explain the limitation in the final response and report any other verification performed. Do not block the implementation solely because a screenshot is unavailable.
